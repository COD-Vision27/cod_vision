## 按代码核对的输出契约

当前 `sp_vision_ros/configs/standard3.yaml`、`standard4.yaml`、`standard3_high_rate.yaml` 默认均为 `yolo_name: yolov5`，读取 `sp_vision_25/assets/yolov5.xml`。

输入是 `float32 [1,3,640,640]` RGB/255。C++ 在左上角按比例缩放，右侧/下侧补黑；不是居中 letterbox。原始相机输入由 OpenVINO 预处理做 BGR→RGB 和 /255。

原模型输出 `float32 [1,25200,22]`，候选顺序为 stride 8/16/32 各3个锚框、每个锚框遍历行列。22列如下：

| 列 | 含义 |
|---|---|
| 0:8 | 四点像素坐标：左上、左下、右下、右上（TL BL BR TR） |
| 8 | objectness 原始 logit；C++ 会 sigmoid，不能提前 sigmoid |
| 9:13 | blue、red、gray、purple 颜色 logits |
| 13:22 | sentry、1、2、3、4、5、outpost、Bs、Bb 编号 logits |

`YOLOV5::parse` 将四点重排为 TL TR BR BL 后构造 `Armor`。训练标签保持原始输出顺序。

数据集每行是13列：

```
class_id cx cy width height x0 y0 x1 y1 x2 y2 x3 y3
```

`class_id=color_id*9+number_id`，其余是相对图像宽高的归一化坐标。bbox 是四点的包围框；这是本训练框架的数据编码，**不代表网络是36类普通检测器**。网络头仍是独立的4类颜色和9类编号。

此外保留 `meta/<split>/*.json`：原始四点、可见性、资产版本、随机种子、场景分组、图像校验和。无目标帧写空 txt。不得把部分遮挡而未标注的装甲帧直接当负样本；本框架拒绝该类不明确帧。需要支持遮挡关键点时，应另外扩展标签与损失，不能悄悄改这份契约。

## 原结构如何训练

`model.py` 读取随工程打包的原 XML/BIN，按 IR 的连接关系构造 PyTorch FX 计算图，将卷积、分组卷积、线性层权重及其融合偏置恢复为 FP32 参数，保留 MobileNetV3、PAN 分支、原锚框、坐标解码、类别顺序；共1,232,796个可训练参数、158组参数。当前实现限定这份 IR 支持的算子，遇到不支持的算子直接报错。

这是**原推理计算图的可微分恢复和微调框架**。IR 已融合 BatchNorm，不能从中恢复原训练仓库的 BN 运行统计、原始训练损失与优化器。这里使用新实现的锚框分配、四点回归、objectness focal BCE、颜色和编号 CE。保存的图、权重与原推理图对照通过，不能宣称复现了上游完整训练配方。

上游来源：[SP 项目](https://github.com/TongjiSuperPower/sp_vision_25)、[RobotPilots 模型说明](https://github.com/broalantaps/RobotDetectionModel)。上游 README 的文字颜色顺序与本项目解码实现可能有表述差异，本框架以本项目 C++ 的0=blue、1=red为准。
