# 装甲合成数据与训练流水线 · building

当前工作是构建本机的数据生产框架。2027装甲尚无具体图片、显示样式或设计图，资产注册表保持 `awaiting_reference`；不沿用旧装甲尺寸假装完成新模型。

## 已确定的技术组合

- **场景/仿真软件：Blender 4.2.1**。承载未来装甲、机器人与环境资产。
- **批量渲染框架：BlenderProc 2.8.0**。在本机GPU上做相机、光照与场景采样。
- **一键标注插件：SP Armor Labels（项目自建，building）**。Blender面板入口与无界面批采共用几何真值writer。输出同帧RGB、TL/BL/BR/TR四点、颜色、编号及项目YOLO标签；不调用旧检测器。
- **训练后端：PyTorch**。沿用项目模型输出契约，接现有训练/导出模块。旧模型权重仅是初始化选项，不参与生产标注。

## 工程链路

```text
后续真实参考资料
  → 装甲/显示资产与四点绑定 registry
  → Blender + BlenderProc（本机GPU）
  → SP Armor Labels（同帧几何真值、一键标注）
  → 数据集导入与按场景划分
  → 项目兼容的YOLO训练（本机GPU）
  → 导出接口
```

`configs/pipeline.json` 是流水线定义；`registry/armor2027.pending.json` 是尚未填充的资产接口；`armor_training/pipeline.py` 串联阶段。规划可以在开发端读取，执行只允许显式启用的本机进程。资产空缺时停止在等待资产状态，不生成假定的2027训练数据。
