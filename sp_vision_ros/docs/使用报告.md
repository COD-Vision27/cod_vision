## 1. 接入方式与隔离

新增独立目录 `sp_vision_ros`。它通过 CMake 引用 SP 源码构建 `sp_sim_core`，源码只读复用，不复制另一套自瞄算法，也不修改原项目。适配器 `sp_sim_auto_aim` 实际调用：

```text
Bevy RGB 渲染 + 同帧姿态 + CameraInfo
  → ROS2 精确时间戳配对
  → YOLOv5 / 传统角点修正
  → Solver（PnP、外参、世界姿态）
  → Tracker / Target 的 EKF
  → 最新目标副本
  → Planner（时间补偿、弹道预测、参考轨迹）
  → yaw TinyMPC + pitch TinyMPC
  → ROS2 SpGimbalPlan
  → 仿真云台 PID、速度前馈、加速度约束
  → 仿真弹丸及装甲命中遥测
```

原 `standard`、`standard_mpc`、CBoard、Gimbal、串口/CAN 协议和实机配置保持原样。新增 ROS 程序完全不创建硬件 I/O 对象。仿真旧话题 `/rm_gimbal/cmd` 保留，新版使用独立 `/sp_vision/sim/plan`，两种指令不要同时发送。

原项目完整性检查见 `artifacts/sp_vision_integrity.json`：对接入开始时的 230 个源码、配置和资产文件进行 SHA-256 校验；构建产物、日志、录制目录不参与比较。相对远端原版基线，仿真 131 个检查文件中 121 个不变，修改 10 个通信/控制/测试场景文件并新增 1 个 ROS 消息；原配置、资产、装甲构造和弹丸实现不变。详见 [修改范围审计](../artifacts/integration-audit.json)和[相对最小 ROS 基线的补丁](../artifacts/final-simulator.patch)。

## 2. 相机外参的计算

仿真己方使用 `assets/vehicle.glb`。相机跟随代码并不使用 `CAM_DIRECTION` 节点的旋转，而是使用：

```text
相机旋转 = 云台世界旋转 × SHOT_DIRECTION旋转 × Rx(π/2)
相机位置 = 机器人位置 + 云台世界旋转 × CAM_DIRECTION平移
弹丸起点 = 机器人位置 + 云台世界旋转 × SHOT_DIRECTION平移
弹丸方向 = 云台世界旋转 × SHOT_DIRECTION旋转 × [0, 1, 0]
```

因此外参必须按运行代码计算，不能直接抄 glTF 相机节点的旋转。该接入将 SP 的云台坐标原点设在枪口，与弹丸起点一致；轴为前、左、上。OpenCV 光学坐标轴是右、下、前。

设：

```text
M = [[ 0, 0,-1],    Bevy → ROS/SP：[-z,-x,y]
     [-1, 0, 0],
     [ 0, 1, 0]]

O = diag(1,-1,-1)  OpenCV 光学 → Bevy 相机局部坐标
B = R_SHOT × Rx(π/2)
```

实际数值：

```text
p_CAM  = [-0.002016811632, 0.196342125535, -0.060025162995] m
p_SHOT = [-0.001830999972, 0.110288001597, -0.010703999549] m
B ≈ Rx(25°)

R_camera2gimbal = M × O
                 = [[ 0, 0, 1],
                    [-1, 0, 0],
                    [ 0,-1, 0]]

t_camera2gimbal = M × Bᵀ × (p_CAM − p_SHOT)
                 = [0.081068194712,
                    0.000185811659,
                    0.057147504027] m
```

该平移已包含相机相对枪口的前后、高度和横向差。不能把原车 standard3/4 的实测外参或补偿角继续用于仿真。

`scripts/derive_config.py` 读取模型与选中的仿真 TOML，显式生成 YAML 和几何元数据。已有 YAML 默认拒绝覆盖；`--geometry-only` 只更新相机/弹速字段并保留算法调参，TOML 始终保留手动编辑。构建与测试不隐式生成配置。Python 测试用任意机体姿态和三维点验证外参与直接场景变换计算一致。

仿真具有 `CALIB.glb` 标定板。这里采用可精确获取的解析几何，没有把未执行的棋盘格采样写成实测标定。如果需要验证标定流程，可以另行采集棋盘格多姿态图像，检查结果是否与上述几何一致；改变相机跟随代码或模型后应重新计算，而不是沿用旧矩阵。

## 3. 相机内参与仿真配置

默认 RGB 1440×1080，垂直 FOV 45°，Bevy 使用无畸变透视投影：

```text
fx = fy = height / (2 tan(FOV_y/2)) ≈ 1303.675283387 px
cx = 720 px，cy = 540 px
D = [0,0,0,0,0]
```

运行时与 `/camera_info` 比较 K、D 和分辨率；内参变化、固定外参不一致或切换到自由/第三人称相机会使该帧被拒绝并解除控制。回到第一人称后，新的有效帧恢复接入。

仿真 YAML 参考 standard3 的算法参数，保留 YOLOv5、传统角点修正、置信度阈值、Tracker 和 MPC 权重/约束。必要调整：

| 项目 | 仿真值 | 原因 |
|---|---|---|
| enemy_color | blue | 己方模型为红方 |
| yaw_offset/pitch_offset | 0/0 | 解析几何无实机安装残余偏差 |
| camera_matrix、D、外参 | 本文计算值 | 仿真投影和固定安装关系 |
| device | CPU | 减少神经推理与 Bevy GPU 渲染争用；可改 GPU |
| sim_bullet_speed | 25 m/s | 与仿真 `projectile.speed` 一致 |
| 两档附加延迟 | 0 | 真实处理耗时由 Planner 的当前时间补偿覆盖 |
| fire_thresh | 0.0035 rad | 保留 standard3 的规划误差阈值 |
| max_yaw_acc/max_pitch_acc | 50/100 rad/s² | 与标准配置一致 |
| target_timeout_ms | 250 ms | 没有新视觉状态时解除控制 |
| command_timeout_s | 0.25 s | 仿真接收端独立指令看门狗 |

已提供 `configs/standard4.yaml`，保留 standard4 的 `decision_speed`、Aimer 参数和 `fire_thresh=0.003`，使用相同仿真几何，两档附加延迟统一清零。可通过 `--profile standard4` 选择；直接调度闭环时使用 `SP_AIM_CONFIG=configs/standard4.yaml`。例如：

```bash
python3 tools/remote_run.py --env SP_AIM_CONFIG=configs/standard4.yaml \
  --skip-build --scenario static --seconds 30 closed-loop
```


### standard3 与 standard4 的具体差异

这两个文件是不同车辆的参数集合，不能仅凭文件编号判断自瞄版本；执行 `standard_mpc` 才走新版 Planner/TinyMPC 链路。当前工作树的 standard3 还包含已有的 UART 定制，适配器保留这些实机改动。

| 参数 | standard3 | standard4 |
|---|---|---|
| yaw/pitch 安装补偿（度） | 2 / 6.5 | −2 / 0 |
| comming_angle（度） / decision_speed（rad/s） | 55 / 7 | 60 / 8 |
| 高速/低速附加延迟（秒） | 0 / 0 | 0.015 / 0.015 |
| 曝光（ms） / gain | 2.5 / 16.9 | 2 / 16 |
| 相机 fx / fy（px） | 1785.488 / 1785.026 | 1851.707 / 1851.818 |
| 相机→云台平移（m） | [0.131607, 0.103777, 0.024908] | [0.045517, 0.105443, 0.034650] |
| fire_thresh（rad） | 0.0035 | 0.003 |
| 能量机关 fire_gap / predict（秒） | 0.700 / 0.120 | 0.520 / 0.100 |
| 实机通信 | by-id 串口、UART44 收发、默认模式和弹速等已有定制 | `/dev/gimbal` 与 CAN 参数 |

两者使用相同的最大两轴加速度和 MPC Q/R，Tracker 主要阈值也一致。standard4 多了一处值相同的 `min_confidence: 0.8` 重复项，生成器会去重。相机畸变和旋转外参各自不同，仿真配置统一替换为本报告的解析值；能量机关和实机通信参数不进入此次装甲板自瞄节点。

## 4. 时间戳、俯仰与轨迹控制

普通 `/tf` 的发布时刻可能与 GPU 图像读回时刻不同。新增 `/sp_vision/sim/frame_tf` 在 Bevy 的 `ExtractSchedule` 获取渲染帧姿态，GPU 读回完成后同图像一起发布，并使用同一个时间戳。适配器按精确时间戳配对 Image、CameraInfo 和 frame_tf；只保留最新完整帧，缓存最多 16 个尚未配对的时间戳。

接收的是 ROS 系统时间戳。适配器换算到 SP 所需的 `steady_clock` 时间域，Planner 继续用原有时间补偿。两台机器运行时须保证系统时钟同步；调度脚本把算法与仿真放在同一远端主机运行，避免跨主机时钟偏差。

SP 的 yaw/pitch 单位是弧度，yaw 正向向左，pitch 负向向上。仿真弹丸使用枪口局部 +Y，而相机面向局部 -Z。实际枪口目标旋转采用：

```text
R_muzzle_target = Ry(yaw_SP) × Rx(−pitch_SP − π/2)
```

减 π/2 是由物理发射方向决定的，不依赖旧 GimbalCmd 的注释约定。此转换有水平射向和抬头方向的 Rust 测试。

SP 新消息携带两轴角度、角速度、角加速度。仿真在指令间按导数推进参考角度，并将世界参考速度通过同一云台/枪口安装关系转到云台局部轴，再与 PID 反馈相加；最终角速度仍受原 PID 的 max_rate 限制，速度变化另受消息中的 max_acc 限制。更新指令保留 PID 状态与上一周期速度；超过有效期或 `control=false` 删除跟踪状态。

Planner 原有 `fire` 使用参考轨迹与规划轨迹的误差，没有直接检查云台实测误差。适配层保留该判定作为开火建议；执行端使用与实际弹丸发射一致的当前枪口方向，要求与规划方向偏差小于 0.01 rad 才发射。图像同帧姿态有 GPU/推理延迟，只用于 Solver 和诊断，不能代替执行瞬间的对准检查。`allow_fire: false` 可以进行纯跟踪试验。开火仍受仿真原有发射冷却和 10 Hz 限频约束。

## 5. 使用、调试和可复现实验

远程构建、单命令双端演示和直接在目标机双终端启动的命令见 [README](../README.md)。也可 source `scripts/env.sh` 后通过 `ros2 launch sp_vision_ros simulator_aim.launch.py` 启动算法。

运行中按 F3 切换视角；己方和假人的键盘控制沿用原仿真器。启动脚本默认通过 `DAEDALUS_AUTO_AIM=1` 强制接收指令；以 `DAEDALUS_AUTO_AIM=0` 启动时可用 F5 切换自瞄订阅。算法识别到目标才发送有效控制。建议先用静态场景检查框、姿态和枪口，再运行旋转/横移场景。

```bash
source sp_vision_ros/scripts/env.sh
ros2 topic list
ros2 topic hz /image_raw
ros2 topic echo /sp_vision/sim/diagnostics
ros2 topic echo /sp_vision/sim/plan
```

闭环脚本 `tests/closed_loop.py` 自动启动两端、观察检测/规划诊断、等待仿真结束并检查断流解除控制。`artifacts/*_metrics.jsonl` 是仿真原有的逐发弹丸遥测；有开火命令不等于有命中，测试结果分别列出控制、开火建议、实际发射和实际命中。

### 目标机实测

已先回滚并验证原版，再恢复必要接入。目标环境为 ROS2 Jazzy / RTX 4060，实际静态、旋转和横移都完成了图像识别、云台控制、物理发射和蓝方装甲命中；断流后解除控制。几何、ROS 故障输入和 72 项 Rust 测试通过。完整数据和判据见 [测试说明](测试说明.md)。

原先关于材质、光照、网格层级与 CCD 的尝试没有恢复。此次只保留实际复现后修复的 ROS 导入与 CENTER 查询、新消息和同帧姿态、导数控制以及显式开启的测试场景。独立仿真 TOML 仅关闭无关 Livox 捕获；原阴影、500 lux 照明和 8 个物理子步保持原配置。

## 6. 限制和工程注意事项

- 新接入只运行新版装甲板自瞄，未把能量机关分支接入。
- `sim_bullet_speed` 是配置值。修改仿真弹速后重新生成 YAML；原 Planner 接受 10–25 m/s，区间外会回落到 22 m/s，因此生成器拒绝区间外的仿真弹速。启用气动阻力后，原 SP 无阻力弹道模型不再完全匹配。
- 原 Tracker/Target 的运动模型和收敛判断保持原样；敌方剧烈加减速、遮挡、类别切换等仍受原算法能力限制。己方运动产生的相对位移也会进入原有目标估计，没有新增独立平移里程计融合。
- ROS2 进程应与仿真使用相同 domain 和 RMW；旧控制话题与 SP 轨迹话题不要同时驱动云台。
- CPU/GPU 推理速度、画面亮度和模型对仿真贴图的泛化能力会影响闭环性能。通过实际命中遥测评估，不能用几何测试通过代替命中率。
- 适配器没有修改 SP 中已有的算法细节；原项目单独运行时也不受仿真开火反馈门限、ROS 看门狗等额外规则影响。


实机标定与一键部署工具见 [sp_deploy](../../sp_deploy/README.md)；实际相机/电控采集与实机命中尚未执行，不能把仿真资格当作实机成绩。
