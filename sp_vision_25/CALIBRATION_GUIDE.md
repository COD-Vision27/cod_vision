## 1. 标定解决什么问题

本项目至少需要三组几何参数：

| 参数 | 作用 | 对应 YAML 字段 |
|---|---|---|
| 相机内参 | 把三维相机坐标投影到像素，或由像素点恢复目标位姿 | `camera_matrix`、`distort_coeffs` |
| 相机到云台外参 | 把相机坐标中的目标变换到云台机械坐标 | `R_camera2gimbal`、`t_camera2gimbal` |
| 云台轴到 IMU 本体轴关系 | 把 IMU 姿态解释为项目定义的云台姿态 | `R_gimbal2imubody` |

内参描述镜头和成像传感器，外参描述相机怎样安装在云台上。两者不能互相替代：即使内参重投影误差很小，相机在云台上有几厘米偏移或几度倾斜时，世界坐标仍会错误。

### 1.1 相机内参模型

针孔模型的内参矩阵为：

```math
K=
\begin{bmatrix}
f_x&0&c_x\\
0&f_y&c_y\\
0&0&1
\end{bmatrix}
```

变量含义：

- `f_x`、`f_y`：以像素为单位的水平和竖直焦距；
- `c_x`、`c_y`：主点坐标，通常接近图像中心；
- `K`：YAML 中按行展开的 `camera_matrix`。

畸变参数输出为：

```text
[k1, k2, p1, p2, k3]
```

- `k1,k2,k3`：径向畸变，描述越靠近画面边缘越明显的桶形或枕形弯曲；
- `p1,p2`：切向畸变，主要描述镜头和传感器不完全平行产生的偏移；
- 当前程序使用 `CALIB_FIX_K3`，所以 `k3` 被固定为 0。

### 1.2 手眼外参模型

手眼标定通常写成：

```math
A_iX=XB_i
```

其中：

- `i`：第 `i` 组相对运动；
- `A_i`：云台/IMU 在两次采集姿态之间的运动；
- `B_i`：相机观察到的标定板在两次图像之间的相对运动；
- `X`：待求的相机与云台之间固定变换；
- 乘法表示旋转和平移组成的刚体变换复合。

直观地说，同一次转动既被 IMU 看见，也会让标定板在相机画面中的姿态发生变化。标定算法寻找一个固定的 `X`，使两套运动相互一致。

## 2. 本项目使用的标定板

### 2.1 板型

仓库当前程序使用：

```text
对称圆点阵列（symmetric circles grid）
```

不是以下类型：

- 不是黑白棋盘格；
- 不是非对称圆点阵列；
- 不是 ChArUco；
- 不是 AprilTag 或 ArUco 标定板。

源码调用：

```cpp
cv::findCirclesGrid(
  img,
  pattern_size,
  centers_2d,
  cv::CALIB_CB_SYMMETRIC_GRID);
```

`calibrate_handeye` 和 `calibrate_robotworld_handeye` 省略了最后一个 flag，但 OpenCV 默认值为 `CALIB_CB_SYMMETRIC_GRID`，所以三者期望相同板型。

### 2.2 当前默认规格

`configs/calibration.yaml` 定义：

```yaml
pattern_cols: 10
pattern_rows: 7
center_distance_mm: 40
```

含义如下：

| 字段 | 含义 | 当前值 |
|---|---|---:|
| `pattern_cols` | 每行圆心数量 | 10 |
| `pattern_rows` | 每列圆心数量 | 7 |
| `center_distance_mm` | 水平和竖直相邻圆心距离 | 40 mm |

这里统计的是“圆心数量”，不是圆之间的空格数，也不是棋盘格方块数量。

10×7 圆心阵列的圆心跨度为：

```math
W_c=(10-1)\times40=360\text{ mm}
```

```math
H_c=(7-1)\times40=240\text{ mm}
```

式中 `W_c`、`H_c` 分别是最左到最右圆心、最上到最下圆心的距离。板材实际尺寸还要加上圆半径和外边距，因此应大于 360×240 mm。

### 2.3 圆点直径

源码只使用圆心距离，不读取圆直径。圆直径影响检测稳定性，但不会直接进入标定几何模型。

对于 40 mm 圆心距，可以把 16 至 24 mm 直径作为制作起点，即直径约为间距的 40% 至 60%。这是图案可检测性的经验建议，不是项目源码规定值。最终应在实际工作距离、曝光和焦距下验证 `findCirclesGrid` 能稳定识别。

### 2.4 一个必须注意的硬编码

三个计算程序从 YAML 读取行列数，但 `calibration/capture.cpp` 的实时预览把标定板写死为：

```cpp
cv::Size(10, 7)
```

因此：

- 使用默认 10×7 标定板时，采集和计算一致；
- 修改 YAML 为其他规格时，`calibrate_camera` 会按新规格计算，但 `capture` 的实时检测仍按 10×7 显示；
- 若确实要更换板型或尺寸，应同步修改 `capture.cpp`，最好进一步改成从 YAML 读取。

## 3. 制作和检查标定板

### 3.1 图案要求

- 圆心必须组成规则矩形网格，每一行、每一列都等距。
- 建议黑色实心圆、哑光白底，保持高对比度。
- 标定板必须平整、刚性足够，不能贴在会弯曲的纸板或布面上。
- 图案四周保留清晰白边，避免最外圈圆与板边或背景连在一起。
- 打印或加工时必须关闭“适应页面”“缩放到可打印区域”等自动缩放。

### 3.2 实物测量

打印后至少测量：

1. 横向相隔多个圆的总距离；
2. 纵向相隔多个圆的总距离；
3. 两条对角线；
4. 板面平整度。

例如测量第 1 到第 10 列圆心总距离应为约 360 mm。跨多个间距测量可以降低单次找圆心造成的误差。若实测不是 40 mm，应把 `center_distance_mm` 改成实测值，而不是继续使用设计值。

### 3.3 板型识别自检

在正式采集前，先确认：

- 画面能检测出完整 70 个圆心；
- 绘制的角点顺序覆盖整块板；
- 板靠近画面边缘或倾斜时仍能识别；
- 没有镜面反光让黑圆中间发白；
- 圆点没有因失焦、运动模糊或过曝粘连。

## 4. 相机内参标定

### 4.1 固定所有成像条件

标定前确定并保持：

- 相机分辨率；
- ROI/裁剪方式；
- 像素 binning 或 decimation；
- 镜头焦距；
- 对焦环位置；
- 镜头与相机的机械连接；
- 图像是否经过缩放。

标定后改变其中任何一项，都可能使内参失效。曝光和增益本身不改变几何内参，但过曝或噪声会降低圆心检测精度。

### 4.2 图片命名规则

`calibrate_camera` 按下面的顺序读取：

```text
input_folder/1.jpg
input_folder/2.jpg
input_folder/3.jpg
...
```

遇到第一个不存在或无法读取的文件就停止，所以编号必须：

- 从 `1` 开始；
- 连续；
- 扩展名为小写 `.jpg`。

如果目录中有 `1.jpg`、`2.jpg`、`4.jpg`，程序不会读取 `4.jpg`。

### 4.3 采集姿态建议

建议保留 15 至 30 张清晰图像，并覆盖：

- 标定板位于画面中心；
- 标定板靠近四个角和四条边；
- 不同距离，让板占画面约 20% 到 80%；
- 绕水平轴和竖直轴的正负倾斜；
- 少量平面内旋转；
- 保证每张都完整看见所有圆点。

不要只在画面中心正对标定板拍很多近似重复图片。标定需要“姿态多样性”，否则某些参数虽然能算出数值，却会高度相关、对边缘区域约束不足。

### 4.4 运行内参标定

先编译：

```bash
cmake --build build --target calibrate_camera -j"$(nproc)"
```

运行：

```bash
./build/calibrate_camera \
  --config-path=configs/calibration.yaml \
  assets/img_with_q
```

程序逐张显示检测结果，并等待任意键后继续。控制台会输出：

```text
[success] assets/img_with_q/1.jpg
[failure] assets/img_with_q/2.jpg
```

失败图片不会进入标定。全部处理完成后，程序打印可复制到 YAML 的：

```yaml
# 重投影误差: ... px
camera_matrix: [...]
distort_coeffs: [...]
```

程序只打印结果，不会自动覆盖配置文件。

### 4.5 程序实际采用的误差

对第 `i` 张图的第 `j` 个圆心，重投影误差向量为：

```math
e_{ij}=u_{ij}-\hat{u}_{ij}
```

- `u_ij`：图像中实际检测的圆心像素坐标；
- `hat(u_ij)`：使用标定参数和该图姿态重新投影得到的像素坐标；
- `e_ij`：二者的二维差。

当前程序输出的是所有点欧氏距离的算术平均：

```math
\bar e=\frac{1}{M}\sum_{i,j}\left\|e_{ij}\right\|_2
```

- `M`：所有成功图片中的圆心总数；
- `||e_ij||_2`：单个圆心的像素距离；
- `bar(e)`：控制台注释中的“重投影误差”，单位 pixel。

它不是 OpenCV `calibrateCamera` 返回的 RMS 值。两种指标不能不加说明地直接比较。

经验上，当前分辨率和清晰圆点图像下：

- 小于约 0.5 px 通常较好；
- 0.5 至 1 px 应检查模糊、板面平整度和边缘样本；
- 大于 1 px 通常值得重新筛选或采集。

这些是排错参考，不是绝对验收标准。最终还要看距离误差和全画面重投影是否存在系统方向性偏差。

## 5. 不使用海康相机采集内参图片

内参计算只读取 JPG，不关心图片由什么设备采集。因此完全可以使用：

- 普通 UVC USB 摄像头；
- 迈德威视相机；
- 其他程序保存的工业相机原图；
- 已有无压缩或低压缩录像抽帧。

关键要求是：标定图片必须来自之后实际使用的同一相机、镜头、焦距、对焦状态、分辨率和裁剪模式。

### 5.1 使用 USB 摄像头

先用项目测试程序确认画面：

```bash
./build/usbcamera_test \
  --name=video0 \
  --display \
  configs/sentry.yaml
```

当前程序没有按键保存单帧功能，可以使用 V4L2/ffmpeg 工具采集，或写一个只负责 `VideoCapture + imwrite` 的小工具。无论使用什么工具，最终把选中的清晰图片重命名成连续的 `1.jpg`、`2.jpg` 等。

### 5.2 从录像抽帧

可以从保持原始分辨率的录像抽帧，但不要连续取大量相邻帧。相邻帧姿态几乎相同，只会增加重复数据。应从不同位置、距离和倾角选择清晰帧。

视频经过缩放或电子防抖后，其几何关系可能和实时原图不同。用于标定的帧应尽量来自算法实际接收的图像链路。

### 5.3 为什么手机拍标定板不能标定机器人相机

内参属于“相机 + 镜头 + 分辨率”的组合。手机照片只能标定手机自身，不能产生海康、迈德威视或 USB 主相机可用的 `camera_matrix`。

## 6. IMU 坐标轴关系

### 6.1 `R_gimbal2imubody` 的意义

`R_gimbal2imubody` 是一个 3×3 旋转矩阵，把项目定义的云台轴向量转换到 IMU 本体轴。它处理的是轴方向和安装朝向，不是相机外参。

源码构造世界旋转：

```math
R_{g\to w}=R_{g\to i}^{T}R_{i\to a}R_{g\to i}
```

其中：

- `R_g_to_i`：`R_gimbal2imubody`；
- `R_i_to_a`：IMU 四元数给出的本体坐标到绝对坐标旋转；
- `R_g_to_w`：最终使用的云台到世界旋转；
- 上标 `T`：矩阵转置，对旋转矩阵等于逆矩阵。

### 6.2 如何检查轴方向

`capture` 会在图像上显示由四元数计算出的 Z/Y/X 欧拉角。手动只转动一个机械轴，检查：

- 只转 yaw 时，主要变化的是 yaw；
- 只转 pitch 时，主要变化的是 pitch；
- 正方向与项目约定一致；
- 静止时没有明显持续漂移；
- 跨越角度边界时变化连续。

若一个机械轴转动导致两个欧拉角大幅变化，先检查 IMU 安装方向和 `R_gimbal2imubody`，不要通过修改相机外参掩盖轴定义错误。

## 7. 手眼标定数据采集

### 7.1 与内参采集的区别

内参标定只需要图片。手眼标定每个样本必须包含：

```text
N.jpg  标定板图像
N.txt  同一图像时刻的 IMU 四元数
```

文本内容只有四个数：

```text
w x y z
```

注意这里没有录像格式中的时间戳。`capture` 会用图像时间戳查询对应 IMU 姿态，再按 `w,x,y,z` 写入文件。

### 7.2 采集前提

- 已完成内参标定，并把 `camera_matrix`、`distort_coeffs` 放入标定 YAML；
- `R_gimbal2imubody` 已核对；
- 工业相机能稳定取流；
- CAN 能稳定收到 IMU 四元数；
- 标定板在整个采集期间固定不动；
- 相机与云台之间的安装不发生松动。

### 7.3 使用项目采集程序

```bash
./build/capture \
  --output-folder=assets/img_with_q \
  configs/calibration.yaml
```

交互按键：

- `s`：保存当前图片和四元数；
- `q`：退出。

输出示例：

```text
assets/img_with_q/1.jpg
assets/img_with_q/1.txt
assets/img_with_q/2.jpg
assets/img_with_q/2.txt
```

程序只调用 `std::filesystem::create_directory` 创建最后一级目录。如果父目录不存在，应先手动创建完整父路径。

### 7.4 姿态覆盖要求

建议采集 20 至 40 组有效样本，重点是旋转轴和角度多样性：

- 多个不同 yaw；
- 多个不同 pitch；
- yaw 与 pitch 组合姿态；
- 正负方向都要覆盖；
- 每次变化应有足够角度，不要全是 1 至 2 度的小运动；
- 所有姿态中标定板必须完整清晰可见。

如果所有样本只绕同一根轴旋转，手眼问题可能退化：某些平移或旋转分量缺少约束。样本数量多不能弥补运动方向单一。

### 7.5 为什么标定板必须固定

算法假设世界中的标定板不动，观测变化全部由云台和相机运动产生。如果采集中有人移动了板，算法会把板的运动错误解释成相机与云台的安装关系。

### 7.6 不用海康相机做手眼标定

计算程序本身不依赖海康相机，只要已有成对 JPG/TXT 就能运行。采集阶段可以使用其他相机，但必须同时解决：

- 图像时间戳与 IMU 姿态对齐；
- 每张图保存对应 `w,x,y,z`；
- 使用该相机自己的内参；
- 相机必须刚性安装在待标定云台上。

普通 USB 相机的缓存通常比工业相机更深。若仅在程序收到帧时读取当前 IMU，得到的姿态可能晚于真实曝光时刻，转动中会造成系统性手眼误差。最好使用硬件时间戳；没有时应缓慢转动、停稳后采集，并测量延迟。

## 8. 计算手眼外参

### 8.1 更新标定配置

在运行手眼计算前，`configs/calibration.yaml` 至少要包含：

```yaml
pattern_cols: 10
pattern_rows: 7
center_distance_mm: 40

R_gimbal2imubody: [1, 0, 0, 0, 1, 0, 0, 0, 1]

camera_matrix: [...]
distort_coeffs: [...]
```

仓库当前默认 `configs/calibration.yaml` 没有 `camera_matrix` 和 `distort_coeffs`。完成内参标定后必须手动补入，否则手眼程序会在 YAML 读取时失败。

### 8.2 标准手眼标定

运行：

```bash
./build/calibrate_handeye \
  --config-path=configs/calibration.yaml \
  assets/img_with_q
```

程序对每一组数据：

1. 读取 `N.jpg` 和 `N.txt`；
2. 由四元数计算云台到世界旋转；
3. 检测对称圆点阵列；
4. 用 IPPE PnP 求标定板相对相机姿态；
5. 调用 `cv::calibrateHandEye`；
6. 输出 `R_camera2gimbal` 和 `t_camera2gimbal`。

位移在 PnP/标定计算中以 mm 表示，输出前程序执行 `/=1e3`，所以最终 `t_camera2gimbal` 的单位为 m，与运行时 Solver 一致。

### 8.3 Robot-World/Hand-Eye 联合标定

运行：

```bash
./build/calibrate_robotworld_handeye \
  --config-path=configs/calibration.yaml \
  assets/img_with_q
```

该程序调用 `cv::calibrateRobotWorldHandEye`，除了相机到云台外参，还同时估计标定板相对世界坐标的姿态。控制台附加输出：

- 标定板到世界原点的水平距离；
- 标定板相对竖直摆放的偏角；
- 相机相对理想安装方向的偏角。

这些诊断量可以帮助发现板没有固定竖直、世界轴定义错误或外参结果明显不符合机械安装。

### 8.4 两个程序怎么选

| 程序 | 特点 | 建议用途 |
|---|---|---|
| `calibrate_handeye` | 直接求相机到云台关系，接口较简单 | 作为基础结果 |
| `calibrate_robotworld_handeye` | 同时估计世界与标定板关系，输出更多诊断 | 交叉检查和项目当前完整标定 |

可以在同一数据集上运行两者。结果不应完全逐元素相同，但若旋转方向、平移数量级或符号差异巨大，应先检查坐标约定、数据同步和姿态覆盖，而不是任选一组复制。

### 8.5 输出矩阵格式

`R_camera2gimbal` 是 3×3 矩阵按行展开：

```yaml
R_camera2gimbal: [r00, r01, r02,
                  r10, r11, r12,
                  r20, r21, r22]
```

`t_camera2gimbal` 是三维平移：

```yaml
t_camera2gimbal: [tx, ty, tz]
```

其中 `tx,ty,tz` 的方向由云台坐标轴定义决定，单位 m。不要根据肉眼认为“相机在左边，所以 tx 应该为负”就手工改符号；应先核对坐标轴和变换方向。

## 9. 标定结果验证

### 9.1 内参验证

使用没有参与标定的新图片：

1. 检测圆心；
2. 用 PnP 求标定板姿态；
3. 将三维圆心重投影；
4. 检查全画面误差方向。

好的结果不仅平均误差小，还应满足：

- 画面中心和四角都没有明显系统偏移；
- 不同距离下误差没有持续增大；
- 左右边缘不会分别向相反方向偏离；
- 估计距离与实测距离大致一致。

### 9.2 外参静态检查

将目标固定，云台保持不动：

- PnP 相机坐标应稳定；
- 变换后的云台坐标应符合目标实际方向；
- 世界坐标与云台坐标在初始姿态下关系合理。

### 9.3 外参动态检查

固定标定板或装甲目标，只转动云台。若姿态和外参正确：

- 目标在像素中会移动；
- 目标在相机坐标中会变化；
- 目标在世界坐标中应近似保持不动。

世界坐标随 yaw 呈周期摆动，通常说明旋转外参或 IMU 轴关系错误；随角速度出现方向相关滞后，通常说明图像和 IMU 时间没有对齐。

### 9.4 项目验证程序

`handeye_test` 会构造世界坐标网格并投影到真实画面：

```bash
./build/handeye_test \
  --config-path=configs/handeye.yaml \
  --display
```

仓库当前没有 `configs/handeye.yaml`，所以不能直接照默认值运行。需要准备包含以下字段的配置：

- 相机与 CAN 字段；
- 内参与手眼外参；
- `height`；
- `grid_num`；
- `grid_size`；
- `delay`。

这也是当前项目文档和配置资产之间的缺口。不要把默认路径存在当作文件真实存在。

### 9.5 正交性检查

旋转矩阵应满足：

```math
R^TR\approx I,\qquad \det(R)\approx1
```

- `R^T`：旋转矩阵转置；
- `I`：3×3 单位矩阵；
- `det(R)`：矩阵行列式；
- `approx`：允许浮点误差下的近似相等。

若 `det(R)` 接近 `-1`，矩阵包含镜像反射，不是合法三维旋转；若 `R^T R` 明显偏离单位矩阵，通常是复制、行列顺序或数据损坏问题。

## 10. 常见失败模式

### 10.1 一张图都检测不到圆点

检查：

- 是否误用了棋盘格或非对称圆点板；
- 是否确实是 10 列 × 7 行圆心；
- 黑白是否反差足够；
- 圆是否因模糊而互相粘连；
- 图案是否被裁掉；
- YAML 行列是否写反；
- 图片扩展名是否为 `.jpg`。

### 10.2 只在正视时能检测

可能是圆太小、曝光不足、板面反光、背景杂乱或倾斜后圆点变成过扁椭圆。应改善照明、增大圆点在像素中的尺寸，并避免极端倾角。

### 10.3 重投影误差小但测距错误

可能原因：

- `center_distance_mm` 与实物不一致；
- 图像在进入算法前被缩放；
- 使用了不同分辨率的内参；
- 标定板打印比例错误；
- 镜头对焦位置发生变化。

重投影误差主要衡量“模型能否解释像素”，错误的物理尺度仍可能得到很小的像素误差，但会让所有距离按比例错误。

### 10.4 手眼平移数值异常

检查：

- 相机内参是否正确；
- 圆心间距是否以 mm 填写；
- 输出 `/1000` 后是否按 m 写入配置；
- 标定板是否固定；
- 是否只有单轴小角度运动；
- 图像和四元数是否错位；
- `w,x,y,z` 顺序是否正确。

### 10.5 转云台时世界目标跟着转

优先检查：

1. `R_gimbal2imubody`；
2. 四元数含义和分量顺序；
3. `R_camera2gimbal` 的方向是否被当成逆变换；
4. 图像/IMU 时间同步；
5. 相机是否在标定后移动。

### 10.6 外参每次标定差异很大

把数据分成两半分别标定。如果结果不稳定，通常说明数据退化或同步误差，而不是“多跑几次取平均”就能解决。应增加不同轴向的大角度姿态，剔除模糊图，并确认板和相机安装刚性。

### 10.7 程序在某个编号提前结束

三个标定程序遇到第一张空图就停止。检查是否缺少中间编号，或 OpenCV 是否能读取该 JPG。手眼标定还应检查同编号 TXT 是否存在且包含四个有效数字。

## 11. 重新标定的触发条件

出现以下任一情况应重新做内参：

- 更换相机；
- 更换镜头；
- 调整变焦或明显重新对焦；
- 改变传感器输出分辨率、ROI、binning；
- 镜头座松动；
- 图像链路新增几何缩放或裁剪。

出现以下任一情况应重新做手眼外参：

- 相机支架拆装或受撞击；
- 云台、枪管或相机相对安装位置变化；
- IMU 重新安装或轴定义变化；
- 更换相机后端；
- 世界坐标随云台转动出现新的周期误差。

`yaw_offset` 和 `pitch_offset` 是包含枪管、机械装配和弹道误差的射击偏置。它们不属于内参或手眼外参，完成几何标定后仍需单独实测，但不应拿它们掩盖明显的坐标变换错误。
