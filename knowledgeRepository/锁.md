## 锁： `std::mutex`

#### 一个程序访问一片内存，想修改但不想同时让别的程序修改，此时可以给要修改的变量/内存加一把锁

#### 最简单的示例

```cpp
std::mutex mutex_;
mutex_.lock()
```

#### 如果别的程序也想访问这些内容，也需要调用`mutex_.lock()`,如果此时发现其他程序已经调用，则会阻塞。

#### 当程序修改完后就可以解锁让其他程序工作了，此时解锁即可。

```cpp
std::mutex mutex_;
mutex_.lock()
/*
do some work...
*/
mutex_.unlock()
```



#### 如果觉得麻烦，还存在自动锁:`std::lock_guard`

#### 示例:`std::lock_guard<std::mutex> lock(mutex_);`

#### 当进入一个作用域的时候，自动构造一个锁，离开时自动解锁



#### 更加灵活的锁：`std::unique_lock`

#### 示例:`std::unique_lock<std::mutex> lock(mutex_);`

#### 与`lock_guard`相比，除了自动上锁解锁外，它还可以手动上锁和解锁,而且还可以搭配`条件变量`的wait.

#### 条件变量: `std::condition_variable`

#### 在某些情况，比如我是流水线中游，假设上游发送的任务完成了，那么我不需要一直检查当前是否还有任务，而是进入休眠，当上游发生任务时，再唤醒我，条件变量就是实现这个的

#### 示例: `std::condition_variable cond_var_;`

#### 使用:

```cpp
std::unique_lock<std::mutex> lock(mutex_);
cond_var_.wait(lock, [this]() { return !main_queue_.empty(); });
```

#### 这里条件变量调用wait,意思是当队列不空的时候才上锁。如果是空的，我就休眠，等待唤醒。

#### 唤醒代码如下：

```cpp
cond_var_.notify_one();   // 唤醒一个等待线程
cond_var_.notify_all();   // 唤醒所有等待线程
```

#### 研究了一会，这个notify_all()似乎可能会出错，所以用上面即可，同时最好一个条件变量只对应一个wait,如果多应多个wait，使用`notify_one`无法控制唤醒的是哪个wait，此时就只能用`notify_all()`。
