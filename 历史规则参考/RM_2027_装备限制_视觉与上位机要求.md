# RoboMaster 2027 装备限制、视觉与上位机要求

整理日期：2026-10-15。覆盖本目录现有 **RMUC 2027 超级对抗赛、RMUL 2027 联盟赛**文件；两项赛事分别适用，不互相套用。

## 1. 先回答装备选型最关心的问题

**目前不能用现有四份 2027 文件完成整机装备合规审查：新加入的是 RMUC 比赛规则与参赛手册，仍缺 2027 机器人制作规范、通信协议。** 比赛规则也明确要求机器人符合 2027 制作规范。

| 具体问题 | 依据现有 2027 文件能得出的结论 |
|---|---|
| 能不能装工业相机、自瞄计算机？ | 文件讨论机器人感知、自动控制与运算平台，但未提供这些自研设备的完整制作约束；不能从中得出禁止自瞄，也不能认定设备安装无限制 |
| 限制相机品牌、数量、分辨率、焦距、帧率吗？ | **已查阅的四份 2027 文件未给出明确数值上限**；需补查制作规范与增补。官方图传画面的限制与自研工业相机限制是两件事 |
| 限制 NUC、Jetson、GPU、CPU、内存、模型或 ROS 吗？ | 未找到指定型号、计算性能、操作系统或算法框架要求；这不等于已经确认任意配置均可通过检录 |
| 上位机是不是也只能用 50／75／100 W？ | 比赛表中的对应限制是**底盘功率**，不能直接当作机载计算机或整机总功率上限。计算机供电、容量、电压、布线和设备功耗约束需回到制作规范 |
| 能带笔记本放操作间吗？ | 不能以普通自带电脑身份任意使用；**自定义终端是明确的例外**，需符合其要求并通过检录 |
| 能用 Wi-Fi、蓝牙、手机热点或场外电脑辅助吗？ | 不应作为可用方案。2027 明确禁止擅自架设无线设备、带无线调试器进赛场、未经许可对外通信；机载及终端无线部件的具体禁用方式尚需新版制作规范确认 |
| 750 W 是所有上位机的限制吗？ | **不是。750 W 是 2026 制作规范的雷达运算平台端参数，不能套给所有机载计算机，更不能冒称已确认的 2027 数值** |
| 自定义终端可以接收什么？ | 官方图传、己方可获取的赛事信息；可发送官方选手端支持的赛事指令。不能据此扩展为访问所有网络数据或任意控制全部机器人 |
| 联盟赛哨兵能接收雷达／其他车的数据吗？ | **RMUL 哨兵不允许多机通信**；RMUC 则可向所有己方机器人发送，但只能接收雷达数据。必须分开配置 |

## 3. 视觉与上位机受影响最大的 2027 变化

### 3.1 RMUC 新增自适应装甲：瞄准中心不再总是最优

依据：U27 §5.2，p.72–73；该机制列于 §1.2 新赛季主要变更。

- 默认状态：弹丸原始伤害倍率 **1 倍**。
- 已加固区域：原始伤害倍率 **0.5 倍**。
- 未加固区域：原始伤害倍率 **1.5 倍**。
- 比赛每经过 1 分钟，双方各获得一次可累积的加固机会；己方当局累计命中弹丸数 **≥10** 后，由**雷达**发送指令消耗机会，选择或改变加固中心。
- 选定中心在己方所有机器人、前哨站和基地装甲上统一使用；加固范围是面积 A 的圆，其余为未加固区。
- 命中位置 `(x,y,区域类别)` 通过常规裁判链路给受击方，同时通过雷达无线链路给攻击方。
- 装甲平面坐标系原点在检测面**左下角**，x 向右、y 向上；不能直接使用图像像素坐标发送指令。

面积计算依赖命中率与散布：`Λ=η/σ`，`ρ=Λ己方/Λ对方`，`A=装甲板面积×ρ²/(2+ρ²)`。σ 为命中点到横纵坐标中位数所构成中心的距离中位数；它不是简单的均方差。零命中、σ 为零、圆被边界裁切等实现边界，需结合协议和官方答疑确认。

**研发建议：**自瞄目标点、弹丸落点统计、装甲平面坐标转换和雷达加固决策需要联调。加固圈位置的可获取方式不能想当然；应以协议允许数据为准。该机制只在现有 **RMUC** 文件出现，不能套入联盟赛。

### 3.2 RMUC 新增基地后勤削减：图传与通信性能动态变化

依据：U27 §5.6.1、表5-19，p.94–95。U26 基地机制没有这一后勤系数体系。

定义 Δ 为己方基地已损失血量，`λ=1−Δ/20000`：

| 项目 | 当前规则关系 | 上位机需要注意 |
|---|---|---|
| 机器人交互数据带宽 | 原值 × λ | 不要把平时可用带宽当作整局保证；报文预算应能降级 |
| 图传画面分辨率 | 原值 × λ²；原画面为 1920×1080 | 官方通过面积平均降采样再双线性放大降低清晰度；不能只看输入图像宽高是否变化 |
| 官方选手端 UI | 清晰度不受上述图传降采样影响 | 图传与 UI 要分开处理 |
| 自定义终端图传 | 同样受上述分辨率机制影响 | 自制终端不能规避官方图传清晰度削减 |

还会影响复活、补给回血与远程回血。这里的通信范围写作“机器人交互数据”，具体定义仍要看 2027 通信协议，**不能认定每一种链路或本地相机 USB 带宽都乘 λ**。

**研发建议：**若直接用官方图传做视觉识别，必须验证低清晰度与重新放大后的识别表现；机载工业相机本地采集没有在本条中被规定降分辨率。通信使用优先级、过期丢弃和断链降级，避免低价值信息挤占关键状态。

### 3.3 RMUC 自定义客户端与控制器合并，但 RJ45 并非今年首次出现

依据：U27 §3.3.1、§4.5.3，p.28、61–63；U26 §4.6.3、§5.7，p.62、122。

2027 将两类设备合并为**自定义终端**，可由显示器、运算平台、输入设备组成，也可一体化。操作间内终端允许有线互联，并通过官方 RJ45 接入赛事引擎，接收图传与允许的赛事信息、发送支持的赛事指令。

**年度对比要准确：**2026 RMUC 已经提供 1GbE RJ45、自定义客户端和接收图传能力；2027 的重点是合并设备定义、控制与显示整合以及终端互联，不能写成“2027 RMUC 首次允许网口上位机”。2027 RMUL 本册则新增自定义终端的明确介绍与接口说明。

值得单独注意：M26 S63（p.23）明确禁止不同自定义客户端之间任何形式的直接通信；U27 p.28、L27 p.21 现在明确允许操作间终端之间**有线连接与通信**。这是可确认的权限变化，但许可范围是操作间终端互联，不是机载无线任意互联。

### 3.4 热量、黄牌、飞镖造成的画面异常不是同一种断链

依据：U27 p.65–67、111、123–125；L27 p.30–31、52。

| 触发条件 | 2027 RMUC 明确效果 | 对程序的含义 |
|---|---|---|
| 普通过热 | 锁枪、第一视角图传断开，热量回零后恢复；**小地图、自定义 UI 仍正常** | 过热不是整机重启；不要用“有 UI”判断图传正常 |
| 黄牌界面遮挡 | **图传、小地图、自定义 UI 均遮挡** | 不应将其当作普通视频解码异常 |
| 飞镖命中触发遮挡 | 操作界面、小地图机器人位置、自定义 UI 受遮挡；条文又明确**自定义终端仍正常接收图传等数据** | 不同显示／数据通道分别处理；终端如何呈现受罚状态需按协议及官方要求确认，不能推定可绕过处罚 |
| 地面机器人红牌 | 血量归零、图传断开、多机通信断开、无法复活 | 任务应终止；不能按普通战亡自动返补 |

飞镖遮挡期间，官方还允许在大地图点击发送半自动控制指令，**两次间隔不得短于 3 秒**（U27 p.111）。这不是正常情况下所有控制指令的统一频率限制。

联盟赛已明确过热断图传与红牌处理，但上述 RMUC 的小地图／飞镖细则不直接移植到 RMUL。

### 3.5 重装取代英雄：自瞄参数不能共用一份赛项配置

RMUL 变化见[联盟赛年度对比](./RMUL_2027_规则变化与重点限制对比.md)：英雄改为局内装配模块化发射机构的重装，成功完成流程后限速 16.5 m/s，底盘 50 W。

RMUC 则由**英雄与工程合并为重装**（U27 p.13），先满足使用权限解锁条件，再在工作台安装 42mm 机构，正确识别首发后才视为成功安装；该首发**不计热量、射击初速度和伤害**（U27 §5.7.1，p.108）。这条首发豁免不能从 RMUC 套到 RMUL。

建议单独维护“赛项—兵种—发射机构—裁判状态”配置，不按“编号 1 就是旧英雄”处理。

## 4. 2027 已明确的设备与通信限制

### 4.1 三类“上位机”必须分清

| 位置与用途 | 已确认要求 | 不能混用的条件 |
|---|---|---|
| **机载计算机**：自瞄、导航、控制 | 机器人战亡时切断其他输出、Mini PC 例外这一状态定义仍保留（U27 p.17、L27 p.12）；整机及相关设备须检录 | 例外供电不允许机器人在应断电时继续驱动；接线必须由新版制作规范确认 |
| **雷达运算平台**：场外固定平台 | RMUC 自动运行、最多 1 个调试遥控器；220 V 市电、官方 HDMI 画面输出条件；无备用运算端／传感器端（U27 p.20、28、42） | 雷达市电不能用于普通机载计算机；2026 的 750 W／尺寸不能当作已确认新规 |
| **操作间自定义终端**：界面与赛事交互 | 可有显示、计算与输入设备；仅按许可网口与功能接入，须检录；自带电脑禁令对终端有明确例外 | 不等于可连接场外电脑、互联网服务或架设无线链路；不等于可以任意改变服务器数据 |

**采购结论：**可以先评估性能、接口、散热和体积方案，但目前不宜仅凭比赛规则给某型号相机／Jetson／GPU 整机出具“2027 合规”结论。

### 4.2 操作间的实际接口与摆放

依据：U27 §4.5.3、R29–R33，p.61–63、129；L27 §3.2.5.2、R27–R29，p.28、56。

- 两项赛事均说明每台操作设备至多 **1 个 1GbE RJ45 网口，仅连接自定义终端**；不是给任意网络设备的通用许可。
- **RMUC 重装操作手和指挥手**额外各有一台仅支持 HDMI 输入的官方显示器，分辨率 1920×1080，并提供 HDMI 公头信号线。该额外显示器没有普遍提供给步兵操作手，RMUL 也未作同样承诺。
- RMUC 显示器、转播相机、接口位置固定不可移动；图传接收端支架固定于桌面，接收端**禁止取出支架**。键鼠可以自由移动，终端应放指定区域。
- 机器人自动连接官方图传接收端，自带接收端无法使用；摇杆默认回中，拨杆默认 C 挡。
- 禁止在操作间使用自带耳机或普通电脑，**自定义终端除外**。RMUC 操作手需佩戴对应官方耳机。
- 除雷达的明确市电条件外，不能用官方设备电源给自备设备供电，可自行带电源（U27 R15；L27 R15）。额外 HDMI 显示器不意味着给终端提供额外电源。
- 2027 本册不再像旧版那样承诺 3 个 USB-A 和 1 个 RS232 接口；不要据此锁定必须依赖它们的终端方案。

### 4.3 哨兵、雷达与人工干预的区别

| 对象 | 2027 要求 | 依据 |
|---|---|---|
| RMUL 哨兵 | 全自动；最多 1 个遥控器用于调试；**不允许多机通信** | L27 p.20 |
| RMUC 哨兵 | 自动或半自动；最多 1 个遥控器用于调试；可向所有己方机器人发送数据，**只能接收雷达数据** | U27 p.25 |
| RMUC 雷达 | 自动；最多 1 个遥控器用于调试；可向所有己方机器人发送数据，**只能接收哨兵数据** | U27 p.28 |
| RMUC 指挥手 | 可经官方支持的指令干预哨兵，包括转发小地图标记、兑换、复活、切换姿态等；自动哨兵每次上述人工干预需 50 金币，半自动哨兵无需该干预费用 | U27 p.108–109 |

“半自动干预不消耗金币”指本条干预费，**不能解释为购买弹量、回血等项目本身免费**。终端支持“干预哨兵”的赛事指令，也不代表可以给哨兵增加任意遥控通道。

RMUC 与 RMUL 均要求准备结束后按规定放置调试遥控器；五秒倒计时阶段官方选手端不响应控制指令，包含自定义终端。赛场禁带无线调试器，比赛中不可与操作间外通信；不要依赖比赛期间 SSH 进车或场外人工调参。

## 5. 视觉识别、雷达与感知设备的当前要求

### 5.1 官方视觉目标、有效识别与模块安装

- **相机、保护罩、线束、补光装置都要检查装甲遮挡和整机伸展尺寸。**RMUL R40禁止存活机器人用自身结构遮挡自身任意装甲；RMUC R45也有一般禁令，但重装抓取／携带可移动道具时，允许相关结构与道具遮挡自身1块装甲，不可同时遮挡多块，步兵与哨兵无此携带例外；不得据此设计普通相机支架常态遮挡装甲（U27 p.130–131；L27 p.57–58）。
- 测速或定位模块安装不合规，RMUC 当局按对应模块离线处理（U27 R36，p.129）；定位离线使敌方雷达对本机的标记始终视为准确、己方视为错误（p.71）。
- 装甲判伤看**弹丸接触装甲面的法向速度分量**，不是算法显示的名义初速。RMUC 小装甲的有效检测速度为 17mm >12 m/s、42mm >8 m/s（U27 表5-1，p.64）；RMUL 也为这两个门槛（L27 p.29）。
- RMUC 官方图传相机可辅助判断补给区：标签须在图像中心、模块无明显滚转角，且机器人处于规则规定的补给区（U27 p.73–74）。不能仅把看到标签等同于进入补给区，也不能拿自研相机识别代替官方模块判定。
- 工业相机的固定位置、数量、镜片距灯条、图传天线净空、激光等级等，2027 比赛手册没有给出完整细则，见第 6 节历史参考和第 8 节待办。

### 5.2 雷达：哪些是延续，哪些调整了

依据：U27 §5.7.4，p.112–114；U26 §5.6.6，p.118–121。

| 内容 | 年度判断 | 当前要求／影响 |
|---|---|---|
| 定位误差分级 | 延续 | 准确 d<0.8m；半准确 0.8≤d<1.6m；错误 d≥1.6m |
| 数据中断 | 延续 | 每累计 0.5 秒未收到数据，触发一次错误判定；不是只要断流都保持上次坐标 |
| 标记进度 P | 延续 | 范围 0–150，正确连续上报加速增长、错误／中断加速衰减；敌方 P≥100 获15%易伤，P≥120 获20%易伤 |
| 双倍易伤 | 延续 | 累计使敌方易伤 1 分钟获得一次机会，多目标同时易伤不累加时间；持续 30 秒，每局最多触发 2 次 |
| 电磁波解析、六位密钥及干扰难度 | **2026 已有** | 不是今年首次引入；难度比较仍会影响易伤与机会积累 |
| 信息波内容 | 调整 | 2027 在位置、血量、弹量、增益、经济、增益点状态等基础上，**增加装甲受击信息**；结合自适应装甲使用 |
| 射频具体参数 | 2027 写明后续发布 | 2026 给出的频率、带宽、调制与采样参数，不宜当作 2027 已确定选型参数 |

标记判定频率由雷达发送频率决定，但**该条不是“发送速率无限制”许可**；频率、长度、链路带宽和机器人交互限制需看 2027 通信协议。

雷达信息解析是规则限定的接收任务，不能据此进行主动发射干扰或干扰裁判系统。新版制作规范尚未到位时，也不能沿用旧空中反制激光方案直接定型：U27 已将空中机器人改为空中系统，原空中特殊机制取消，旧雷达激光反制流程不再是现有 2027 本册描述的机制。

### 5.3 打符与飞镖视觉：主要时序延续，不要误报为全新算法要求

U27 §5.6.3（p.97–101）与 U26 §5.5.2（p.100–105）对照，小能量机关、非正在激活的大能量机关仍为 **π/3 rad/s**；正在激活的大能量机关仍为：

```text
spd = a × sin(ω × t) + b
a ∈ [0.780, 1.045]
ω ∈ [1.884, 2.000]
b = 2.090 − a
```

每次进入可激活状态重置参数，实际速度与目标函数时间误差在 500 ms 内。小符命中窗口 2.5 秒、大符双目标先后命中间隔 1 秒、下一组前最多 200 ms 全灭灯等时序仍需处理；不能把短暂灭灯直接判成整套目标丢失。RMUC 禁止用 **42mm 弹丸、飞镖、空中机器人**击打能量机关（U27 p.64）。

飞镖检测模块与引导灯移动时相对位置不变，横向范围仍为初始位置 ±280mm；随机移动目标的 600 ms 换位、末端移动目标发射后 1.2 秒起动再于 600 ms 内完成等视觉预测条件仍在（U27 p.110–111；U26 p.116）。具体镖体摄像头安装和制导结构要求必须等 2027 制作规范，不能沿用旧 S115、S125 直接定性新赛季方案。

## 7. 新增 RMUC 文件对装备规划的其他影响

- **整机阵容改变：**英雄与工程合并为重装；空中机器人改为含机库的空中系统。新阵容为重装1、步兵2、哨兵1，加空中／飞镖／雷达系统；首局至少3台地面机器人，独立赛事阶段注册机器人总数9，备用镖体与空中机器人不计该总数（U27 p.20–21）。
- **雷达与哨兵不配自定义终端：**U27 表3-1 规定这两者终端及后备数量均0；不要把操作间终端有线互联解释为可以额外给雷达配操作手电脑。
- **场地变化：**原飞坡改隧道，新增制高点、机库平台、工作台，取消原飞行区、无线充电装置放置区、停机坪（U27 p.13）。导航地图、遮挡模型及旧无线充电方案均需重审。取消场地放置区本身不替代对所有充电硬件的完整合规定义。
- **代码与图纸可被检查：**争议发生时，有责任展示机械、电路图纸和相关代码、回答技术咨询；不配合最高取消比赛资格（U27 R37，p.129）。这不等于全部代码必须无条件公开开源。
- **评审时间不同：**RMUC 报名截止为 **2026-10-27 15:00**，不是联盟赛的10月30日。RMUC 还需赛季规划、规则测评、中期进度、裁判系统考核、完整形态、总结等评审（UE27 p.15–20），不能沿用 RMUL 的较少环节计划。

## 8. 定型前应补齐的确认清单

以下是落实建议，不是额外官方审批流程。

- [ ] 取得2027制作规范：核对工业相机数量／安装、镜片距离、补光、激光雷达／深度相机、整机与计算平台功耗／尺寸／重量／供电。

- [ ] 分别验证过热、黄牌、飞镖遮挡、红牌、普通失联，避免将全部异常实现为同一种重连逻辑。
